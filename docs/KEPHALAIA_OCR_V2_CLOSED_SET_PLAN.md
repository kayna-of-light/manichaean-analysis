# Kephalaia OCR v2 Closed-Set Plan

Date: 2026-05-13

This plan describes the target pipeline for producing clean Coptic body crops,
line-number ruler metadata, special-region maps, and closed-set character
identification for the Kephalaia manuscript pages.

The target is not generic OCR. The target is a corpus-specific, closed-set OCR
system for one manuscript tradition whose base characters, marks, line-number
structure, and recurring special regions are known in advance.

## Governing Principles

1. Work from page geometry before text interpretation.
2. Keep the line-number column outside the body crop, but preserve it as
   page-level ruler metadata.
3. Do not use Kraken as an active v2 stage. It was too imprecise for this
   manuscript and has been replaced by deterministic ink-component geometry.
4. Classify base characters as a closed set. Any segmented unit that does not
   match the allowed set must be explicitly flagged rather than forced into a
   Coptic label.
5. Treat special regions as layout objects before ordinary line processing.
6. Solve recurring errors at the root: crop rules, line-region rules,
   segmentation rules, cluster/subcluster labels, or special-region handlers.
   Avoid per-glyph manual overrides except for true one-offs.
7. Validate in `temp/` first. Port to production v2 scripts only after review
   artifacts show that the behavior is correct.

## Closed Sets

### Base Character Set

The base classifier should only assign known Coptic base characters. Initial
inventory should be derived from the existing projected assignments in the old
corrected cluster stack, plus any explicit manuscript-specific additions found
during review.

Implementation note: start by extracting the keys from
`output/projects/kephalaia_ocr/clusters_shape_padded_split_bodycrop_corrected_k240/_char_assignments_projected.json`
and filtering to one-codepoint Coptic base labels. Then review whether any
multi-codepoint normalized base labels represent real base forms or connected
legacy labels that should not be in the closed base inventory.

### Mark Set

The mark inventory should remain separate from base characters. Known categories
include:

- above dot
- below dot
- diaeresis-like double dot
- overline or horizontal mark
- lacuna dot
- middle/editorial point
- square bracket components
- unknown mark or damaged mark

Old reference: `build_page_review_sheet.py` already maps mark kinds to combining
marks and display colors. `build_contextual_review.py` already treats mark-like
labels as special labels.

### Special Region Set

Special regions are not ordinary text lines. They must be detected before the
ordinary line splitter runs.

Known initial categories:

- multi-line bracket region
- chapter/title block region
- printed editorial/non-Coptic region
- severe damage/lacuna region that spans line structure
- uncertain special region requiring review

Chapter/title blocks should include the title-like interior plus the flanking
Coptic characters and the character or mark above the block. Multi-line brackets
should preserve the exact body-line or line-number range they span.

### Anomaly Set

Any segmented unit that does not match a base character, mark, or special-region
component must be flagged explicitly.

Suggested anomaly labels:

- `out_of_set_char`
- `damaged_base_candidate`
- `unclassified_mark`
- `noise_or_damage`
- `split_failure_parent`
- `oversegmented_fragment`
- `special_region_unhandled`

This is important because it prevents the classifier from hiding uncertainty by
forcing every shape into the nearest Coptic base character.

## Pipeline Overview

```text
full page image
  -> full-page layout normalization
  -> line-number ruler detection
  -> Coptic body crop only
   -> body-crop ink component geometry
  -> special-region detection
  -> ordinary line extraction
  -> line-local semantic blob extraction
  -> connected-character root splitting
  -> closed-set base classification
  -> mark attachment
  -> anomaly queues
  -> review sheets and invariants
```

## Phase 2: Line-Number Ruler Mapping

### Goal

Map the line-number column as an external ruler while keeping it out of the
Coptic body crop.

### Steps

1. Detect the line-number column on the normalized full page.
2. Segment individual printed line numbers or line-number clusters.
3. Collapse two-digit numbers into a single line-number unit.
4. Estimate the regular line step from the line-number centers.
5. Map each line number to an expected body-line slot.
6. Record gaps, missing line numbers, extra detections, and confidence.
7. Keep all line-number coordinates in both full-page/dewarped coordinates and
   body-relative coordinates where relevant.

### Old Pipeline To Read First

- `_collect_digit_blobs`, `_validate_ln_column`, `_find_line_number_column_extent`, and `_find_left_column_edges_by_projection` in `scripts/projects/kephalaia_ocr/pipeline.py`.
- `compute_column_x_rotated` in `scripts/projects/kephalaia_ocr_v2/deskew_and_crop.py` for the current two-anchor crop logic.

### Output Shape

```json
{
  "page": "127",
  "line_number_column": {
    "bbox": [0, 0, 0, 0],
    "confidence": "strong",
    "line_step_px": 41.2
```

## Phase 4: Body-Crop Ink Geometry

### Goal

Derive page-level ink components, row outlines, baselines, dot rows, and review
overlays directly from the accepted body crops.

### Steps

1. Threshold each accepted body crop at high resolution.
2. Extract connected ink components with stable component IDs and polygons.
3. Exclude true scan/page-edge artifacts while preserving Coptic side markers,
   curly brackets, chapter marks, editorial words, and lacuna dots.
4. Group main text components into row candidates using component geometry and
   ink-profile evidence.
5. Attach marks, dot rows, side markers, chapter marks, and word-like editorial
   rows using deterministic ownership rules.
6. Write exact `component_ids` on every geometry row so later audits can check
   ownership without relying on bbox heuristics.
7. Generate review sheets showing body crop, mask, component polygons, row
   outlines, baselines, and row labels.

## Phase 5: Special Region Detection

### Goal

Detect and tag regions that cannot be processed as ordinary single text lines.

### Steps

1. Use crop geometry, body-geometry rows, line-number ruler slots, and ink
   connected components to find candidate special regions.
2. Detect multi-line brackets:
   - tall vertical/curved bracket-like ink;
   - line range spanned;
   - proximity to body text;
   - relation to line-number ruler.
3. Detect chapter/title blocks:
   - centered or block-like text region;
   - flanking Coptic characters left/right;
   - one character or mark above;
   - local disruption of ordinary line spacing.
4. Detect non-Coptic/editorial printed blocks separately.
5. Mask or route special-region components before ordinary line splitting.
6. Produce review images with region boxes, labels, and line-number ranges.

### Old Pipeline To Read First

- `build_contextual_review.py` for special labels, bracket logic, and geometry-aware decisions.
- `build_page_review_sheet.py` for how special labels and marks are displayed.
- `detect_editorial_markers.py` for non-Coptic/editorial region handling.
- `temp/check_brackets.py`, `temp/test_brackets.py`, and other bracket experiments if further detail is needed.

### Output Shape

```json
{
  "page": "127",
  "regions": [
    {
```

## Phase 7: Line-Local Semantic Blob Extraction

### Goal

Convert ordinary lines into semantic blobs: base candidates and non-base mark
candidates.

### Steps

1. Warp each ordinary line to a normalized strip.
2. Threshold with Sauvola or a validated equivalent.
3. Use connected components to identify ink blobs.
4. Classify initial blob kind:
   - `base_candidate` if it touches the baseline band;
   - `mark_candidate` if it sits above/below or is too small for a base;
   - `fragment_candidate` if it is edge damage or tiny noise.
5. Preserve full provenance:
   - page;
   - body line index;
   - printed line number if available;
   - blob id;
   - warped bbox;
   - original/crop coordinate quad;
   - area;
   - baseline relation;
   - overlap with special regions.
6. Optionally attach raw polygon contours from the crop/page mask so the same
   semantic blob can be rendered as vector ink later.

### Old Pipeline To Read First

- `stage_base_split` in `scripts/projects/kephalaia_ocr/pipeline.py`
- `temp/ink_polygon_exp/polygonize_ink.py` for contour/SVG output, with the caveat that `RETR_EXTERNAL` is not enough for glyph holes.

### Outputs

- `output/projects/kephalaia_ocr_v2/semantic_blobs/keph_pNNN_blobs.json`
- `output/projects/kephalaia_ocr_v2/semantic_blobs/keph_pNNN_blobs_review.jpg`

### Acceptance Gate

classified as a single character.

## Phase 8: Connected Character Root Splitting

### Goal

Split fused base-character parents into child character blobs before final
classification.

### Steps

1. Identify connected parent candidates using:
   - width priors;
   - aspect ratio;
   - column-ink projection;
   - expected line rhythm;
   - closed-set prototype mismatch;
   - optional witness text only as a check.
2. Use morphology and position priors to choose cut locations.
3. Enforce minimum child width and child ink evidence.
4. Record split provenance:
   - parent blob id;
   - split child index;
   - split child count;
   - cut positions;
   - split method;
   - split confidence;
   - expected base only when it is witness/check evidence.
5. Keep unsplittable parents as `split_failure_parent`, not forced characters.

## Phase 9: Closed-Set Base Character Classification

### Goal

Assign each base child blob to one allowed Coptic base character or to an
explicit anomaly class.

### Steps

1. Build normalized glyph patches from semantic base blobs.
2. Preserve aspect ratio and include geometry features.
3. Cluster globally by shape.
4. Create reviewed prototypes per base character.
5. For each blob, compare against:
   - nearest reviewed cluster/prototype;
   - allowed base inventory;
   - line-local geometry;
   - duplicate or impossible labels;
   - contextual plausibility only as a warning, not as the primary labeler.
6. Flag out-of-set or low-margin matches.
7. Use subclustering for mixed clusters before applying labels globally.

## Phase 10: Mark Attachment

### Goal

Attach marks to the correct base character slots after base segmentation and
classification are stable.

### Steps

1. Classify non-base blobs by geometry:
   - above dot;
   - below dot;
   - overline/horizontal mark;
   - diaeresis-like pair;
   - lacuna dot;
   - middle/editorial point;
   - unknown mark.
2. Attach marks using:
   - line ownership;
   - base slot centers;
   - overlap/coverage thresholds;
   - vertical relation to baseline;
   - special-region exclusion.
3. For connected/multi-child labels, attach marks to character slots, not just
   the parent bbox center.
4. Keep unattached marks as reviewable objects.

## Phase 11: Special Region Processing

### Goal

Process special regions through their own route rather than through ordinary
line OCR.

### Multi-Line Bracket Route

1. Confirm line-number range.
2. Extract bracket component geometry.
3. Associate bracket with affected body lines.
4. Keep bracket out of ordinary character classification unless a component is
   explicitly a Coptic base character.
5. Render bracket regions on review sheets as region-level annotations.

### Chapter/Title Block Route

1. Detect title block bbox.
2. Segment internal title text separately.
3. Segment flanking and upper Coptic characters separately.
4. Preserve block structure in output rather than flattening into ordinary line
   order.
5. Create a dedicated title-block review sheet.

### Old Pipeline To Read First

- `build_contextual_review.py` for bracket and special-label behavior.
- `detect_editorial_markers.py` for non-Coptic printed block handling.
- Existing temp bracket/title experiments under `temp/` before designing new
  detectors.

### Outputs

- special-region JSON with per-region routes and extracted components
- region-specific review sheets

### Acceptance Gate

Special regions must be explainable in terms of page structure and line-number
ranges. They should not appear as unexplained noise in ordinary character
review.

## Phase 12: Review, Metrics, And Promotion

### Goal

Make every remaining uncertainty visible and promote only validated logic from
temp experiments to production scripts.

### Review Artifacts

For each page or validation batch, generate:

- crop review image;
- line-number ruler review image;
- body-geometry row review image;
- special-region review image;
- semantic blob review image;
- character classification sheet;
- anomaly sheet;
- split-failure sheet.

### Invariants To Track

- body crops include zero line-number ink;
- body crops include zero footnote/editorial furniture unless region-tagged;
- all line numbers mapped or explicitly missing;
- ordinary body line count agrees with ruler, or discrepancy is flagged;
- all special regions are routed before ordinary line splitting;
- zero recurring fused Coptic parents reach final classification unsplit;
- zero multi-character base labels in final ordinary stream;
- every base candidate has a closed-set or anomaly label;
- every mark is attached, special-routed, or review-queued;
- no out-of-set object is forced into a base character label.

### Promotion Rule

New logic should follow this path:

1. prototype under `temp/`;
2. run on validation pages;
3. inspect review artifacts;
4. run on the full corpus if validation pages pass;
5. summarize failures and invariants;
6. only then port to `scripts/projects/kephalaia_ocr_v2/`.

## Suggested Implementation Order

1. Add layout JSON output to a temp copy of the v2 cropper.

## Expected End State

The completed v2 pipeline should make the manuscript mechanically reviewable:

- the Coptic body crop is clean;
- line numbers act as a ruler outside the crop;
- component-driven body geometry supplies row outlines, baselines, and exact
   component ownership;
- special regions are tagged before ordinary OCR;
- ordinary lines are split into stable base and mark units;
- recurring fused characters are split at the root;
- base characters are classified against a closed inventory;
- marks are attached to known character slots;
- out-of-set shapes remain visible as anomalies.

That is the route to near-perfect corpus-specific OCR without pretending that
every ink blob is an ordinary character or that a generic line detector can be
the final authority.
